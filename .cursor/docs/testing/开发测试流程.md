# 开发测试流程（系统流程）

适用于每一阶段。开发完成 ≠ 阶段完成；**测试勾选后才算完成**。

## 1. 开发完成定义（DoD）

必须同时满足：

- [ ] 阶段文档「开发任务」全部勾选  
- [ ] 代码可运行（入口命令写在阶段文档）  
- [ ] 不提交 `.env` / 密钥  
- [ ] 关键行为与 `architecture.md` / `anti_bot.md` 不冲突  

## 2. 测试分层（必须按序）

### T1 冒烟（每次改完必跑）

- 命令能启动、无立刻崩溃  
- 能连上 MySQL（`python scripts/verify_db_cn.py` 或等价）  
- 中文读写正常  

**通过标准**：命令退出码 0，库内可见预期中文样本或业务行。

### T2 单站功能

对每个启用源站：

- 用约定关键词（至少含「绿植租摆」）跑小样本（1 页级）  
- 检查：有写入 / upsert 不翻倍 / crawl_runs 有记录  

**通过标准**：该站 `crawl_runs.status=success`（或 documented partial），`notices` 新增或更新 ≥ 1（无结果时要有「0 条但成功」说明）。

### T3 增量正确性

1. 同一任务连跑两次  
2. 第二次不应大量重复插入（唯一键冲突应 upsert）  
3. 「新增数」应接近 0 或仅真新数据  

**通过标准**：第二次 `item_count` 新增行数合理；无唯一键报错裸崩。

### T4 反爬/降级

- 模拟或真实遇频控时：有退避/记录，不死循环打爆  
- 验证码站：标记待人工或跳过详情，列表仍可入库  

**通过标准**：`crawl_runs.note` 或日志可见原因；进程正常结束。

### T5 展示/验收（有 UI 的阶段）

- 增量列表能看到新数据  
- 监控能看到最近一次任务  
- 关键筛选项按级联文档工作  

**通过标准**：对照阶段「测试任务」人工点验，截图或文字结果记入阶段文档「测试记录」。

## 3. 谁测什么

| 角色 | 职责 |
|------|------|
| Agent/开发 | 跑 T1～T4，勾选阶段测试项，写测试记录 |
| 你（产品） | 只看阶段文档：开发勾选 + 测试勾选是否齐全；抽查列表/监控是否「看得见」 |

## 4. 失败怎么处理

- 测试失败：阶段标记 **未完成**，修到通过再勾  
- 外部不可抗力（站点挂、要账号）：在阶段文档写 **阻塞原因**，该项标「阻塞」不算通过，也不假装完成  

## 5. 产出物（每次阶段结束）

1. 阶段 md 勾选齐全  
2. `changelog.md` 补一行  
3. （可选）测试记录附命令输出摘要
