## 二、原发寻址一期（crawl/origin.py）

### 2.1 探针实测结论（2026-08-23，无 mock）

| 站点 | 原发线索可得性 |
|------|----------------|
| chinabidding 详情（桥） | **正文不披露来源**（2 样本：「来源」命中均为「资金来源」误报）→ 只能靠标题主体映射 |
| ggzy b 页（HTTP） | 「信息来源：<label>上海</label>」结构化可得；「原文链接」锚点 href 为空且 display:none（JS 动态填充，静态拿不到）；**内容区含结构化字段：项目编号/交易机构/交易底价/成交价格** |
| jsggzy b 页（HTTP） | 静态正文含「来源：苏州市公共资源交易中心（建设工程）+ 原发 URL」 |
| cebpub | 列表 UI 无来源列；详情被 vaptcha 挡（待人工后复探） |

探针产物：`data/web/_origin_probe.json`、`data/web/_origin_probe2.json`。

### 2.2 实现

- `crawl/origin.py`：
  - `origin_lines/origin_url/origin_entity`：来源行解析（标签含「来源」需负向断言排除「资金来源」；噪声切分容忍「阅读次数/我要打印/关闭」等控件文本与词间空白——jsggzy 实测迭代）。
  - `match_entity_map`：主体→原发平台映射（`config/origin_platforms.json`，招商局 `dzzb.ciesco.com.cn`、华润守正 `szecp.crc.com.cn` 已 web_search 核实）。
  - `is_http_fetchable`：ccgp/ggzy/江苏交易中心域可用既有能力直取。
- `crawl/tenderfile.py _extract_ggzy_origin_and_fields`：b 页结构化来源（platformName label）+ 文本来源 URL + **项目编号/成交价格→amount 解析**；无附件时摘要改用 b 页全文（封顶 2000 字，替代 200 字摘要）。
- `crawl/backfill.py`：聚合站行回填时——结构化 origin/fields 优先 → 摘要文本解析兜底 → 命中可直取域时**原发优先二次抓取**（ccgp 取字段、ggzy/jsggzy 取摘要/附件），失败兜底聚合站结果；全部落 `original_url/origin_source/detail_status`，不造假。
- Schema：`notices` 增 `original_url`/`origin_source`（迁移幂等，`sql/schema.sql` 同步）；详情抽屉展示「原发」链接与原发来源。
