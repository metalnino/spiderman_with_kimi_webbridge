# P4 — 展现层对齐（详情抽屉 + 跨站折叠 + 详情回填接线）

> 需求对齐时间：2026-08-2x。三个决策点已与用户确认，见「决策记录」。

## 决策记录

| 决策点 | 结论 |
|--------|------|
| 详情展现形态 | **站内详情抽屉**（点击行弹出，不离开列表） |
| 跨站同条数据处理 | **视图折叠**（存储不动；同题+同城+同阶段折叠为一条，标「多源」可展开；状态/已读/备注只记一次） |
| 详情回填范围 | **调用已开发能力，分级自动/按需**（不新写爬虫；纯存量 raw_json 无详情字段，见数据事实） |
| 阶段与时间线（2026-08 补充） | **公告按招采阶段分割**：招标公告/更正/候选人公示/结果公告/终止流标等；同项目各阶段串成**项目时间线**。所有阶段数据都保留（后续做标书要用历史结果），列表可按阶段筛选 |

## 阶段口径（crawl/stage.py）

rank 即时间线顺序：

| key | 展示名 | 识别依据（标题关键词，跨站一致） |
|-----|--------|-------------------------------|
| intent | 意向预告 | 采购意向 / 采购需求公示 / 招标计划 / 采购预告 |
| bidding | 招标公告 | 招标/采购/询比/询价/磋商/谈判/比选/邀请函/邀请公告/交易/竞价/公开招标/征集公告 |
| change | 更正澄清 | 更正 / 澄清 / 延期 / 变更 / 补充 / 答疑 |
| preselect | 资格预审 | 资格预审 / 资格审查 / 入围名单 |
| opening | 开标评标 | 开标记录 / 开标结果 / 评标结果 / 评标报告 |
| candidate | 候选人公示 | 候选人公示 / 中标候选人 / 成交候选人 / 预中标 |
| result | 结果公告 | 中标结果 / 中标公告 / 结果公告 / 结果公示 / 成交公告 / 采购结果 |
| terminated | 终止流标 | 终止 / 流标 / 废标 / 暂停 / 开标失败 / 采购失败 |
| other | 其他 | 兜底 |

- 标题关键词优先；未命中时用源站 notice_type 编码映射（ZBGG→bidding、ZBGS/succeed→result、change→change 等）；再兜底 other。
- **project_key** = sha1(city|核心名)；核心名 = 标题去阶段词/日期/标点/噪声块（查询ID、相关在信息中、代发、批次编号），**「二次采购」等批次词保留**——同项目不同批次不串，同批次跨阶段跨站点串。
- 入库即算（models.to_row）；存量 `scripts/jobs/backfill_stage.py` 回填（幂等）。
- 折叠与时间线是两个维度：**折叠**=同题同城同阶段（跨站转载）；**时间线**=同 project_key 跨阶段（招标→更正→候选人→结果→终止）。

## 数据事实（探针，2026-08-2x）

- 全库 notices 约 50 行：chinabidding 22 / jiangsu_zhaobiao 20 / cebpub 5 / ggzy 2 / jsggzy 1 / **ccgp 0**。
- 详情字段全空：amount/buyer/agency/open_time/deadline/project_code 全为 NULL。
- 存量 raw_json 只有内部标记（area_id/table_name/id/platform/via），**无可用详情字段** → 回填必须请求详情页，但均为已有能力：
  - ccgp：`detail.fetch_detail` HTTP 直取（runner 已每轮自动 `enrich_source_details`）
  - chinabidding：`sources/chinabidding_detail.fetch_detail_fields`（.env Cookie，**未接线**）
  - jiangsu_zhaobiao / cebpub：`tenderfile.fetch_tenderfile` 桥详情（含江苏自动登录、附件下载、vaptcha 模式）
  - ggzy / jsggzy：`tenderfile._fetch_ggzy_http` 附件模式；列表为 API 通道，先探列表是否已带字段
- 跨站重复：6 组同题双源 = 12 行（24%），全部 chinabidding × jiangsu_zhaobiao；字段互补度为零（两边均无金额/招标人），合并收益=「同一线索只处理一次」+ CRM 计数真实。
- 现有 content_hash = sha1(source_id|external_id)，只做站内去重；跨站折叠是新能力（视图层，不动 schema）。
- 阶段分布（回填后实测）：bidding 17 / result 19 / candidate 7 / other 4 / change 2 / terminated 1；时间线聚合出 12 个项目组（含跨站批次，如「招商积余南京 HW-NYSAB」6 行 bidding→candidate→result 双源）。
- 探针产物：`data/web/_dup_probe.json`、`data/web/_stage_probe.json`。

## 实现范围

### 0. 阶段与时间线（✅ 已完成：stage.py + 迁移 + 回填 + 单测）

- `crawl/stage.py`：classify_stage / project_key（规则见上节）。
- `crawl/models.py` to_row 入库即算；`crawl/db_store.py` UPSERT 带新列。
- 迁移：`scripts/migrate_ops.py` 增 notice_stage/stage_rank/project_key/project_name/summary/tenderfile_path/detail_status + idx_stage/idx_project（`sql/schema.sql` 已同步）。
- 回填：`scripts/jobs/backfill_stage.py`（幂等，--all 全量）。
- 单测：`tests/test_stage.py` 11 例真实标题回归。

### 1. 站内详情抽屉（data/web/ledger_app.html + API）✅

- 行点击 → 抽屉：库内全字段（含 open_time/deadline/region_text/notice_type/bid_status/阶段）+ 原文/详情外链 + CRM 操作区（处理状态/金额确认/备注/已读），改动即时落库。
- **项目时间线**：抽屉内展示同 project_key 的各阶段公告（按 stage_rank + 发布时间），可互相跳转。
- 回填后展示：正文摘要（summary）、附件下载（`/api/notices/{id}/tenderfile`）。
- 「按需回填」按钮（`POST /api/notices/{id}/backfill`）：调用已有详情能力；失败如实展示 error，不造假。

### 2. 跨站视图折叠（crawl/ledger_data.py）✅

- 折叠键：标准化标题 + city（同题同城即同阶段，自然同阶段折叠）；Python 侧折叠后分页，total=折叠后组数。
- 主行选择：有金额者优先 → 发布时间早者 → id 小者；`dup_count/sources/duplicates` 供前端展开各源链接。
- 列表新增**阶段筛选**（`stage` 参数，9 阶段来自 `crawl.stage`）。
- CRM 主体 notice_count 按折叠去重（`build_crm_db.py`，实测：招商商管 11 行→8、招商积余 6 行→3）；顺带修复 entity_suffixes 缺「公司/商管」导致招商系主体漏抽的存量问题。
- 不做存储级硬合并（同题不同阶段=不同线索；误合并风险不接）。

### 3. 详情回填接线（分级）✅ 代码 + 实测

| 层级 | 站点 | 状态（2026-08 实测） |
|------|------|------|
| 自动（随增量） | ccgp | 已有链路（runner 每轮 enrich） |
| 按需（桥摘要） | chinabidding | HTTP 详情实测 405 WAF（2 条确认），**改走桥摘要路径**；Cookie 未配置（.env 无 CHINABIDDING_COOKIE） |
| 按需（ggzy_http 摘要） | jsggzy / ggzy | **列表接口实测仅标题/链接，无字段可复用** → 按需走 tenderfile 摘要 |
| 按需（抽屉按钮） | jiangsu_zhaobiao / cebpub | 桥详情（江苏账号已配置 JIANGSU_ZHAOBIAO_USER）/vaptcha 待办；不逐条自动硬碰墙 |

- 单条回填：`crawl/backfill.py backfill_notice`（ccgp=字段、其余=summary/tenderfile），结果落 summary/tenderfile_path/detail_status。
- 批量跑批：`scripts/jobs/backfill_details.py --source <id> --limit N`（条间冷却，失败如实记录）。

- 迁移走 `scripts/migrate_ops.py`（幂等）。
