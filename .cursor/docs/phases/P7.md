# P7 — 采集岗召回自证与公司视角线索口径

> 触发：用户要求按第一性原理把采集岗优化到「公司可信任」水平。
> 核心命题：公司拿线索做投标决策，最怕的不是噪音，是**「没看到」被当成「没有」**。

## 一、实锤的问题（数据事实）

- **ccgp 召回硬伤**：连续 6 轮（8-22~8-24）raw=20 完全相同（19 条 8 城外 + 1 条窗口外），`max_pages=1` 意味着**永远只扫第一页**——「8城×7-8月交集极少」是扫描策略缺陷的假象，不是真没数据。ccgp 是政府采购主渠道，这是最大召回缺口。
- **0 新增不可自证**：无水位记录，无法区分「真没新数据」与「没翻页/被频控跳过」。
- **线索口径混乱**：列表把招标/结果/终止混在一起，公司视角真正要的是「还能投的」。

## 二、本轮实现

### 1. 水位游标（crawl/watermark.py）——召回自证

- 每站持久化「原始已见 external_id 集合」（**含被城市/日期过滤丢弃的**——下一轮才能越过已见页）。
- 每次出勤合并水位并回报 `wm_new`（本轮新见）/`wm_total`（水位规模）/`pages`（扫描页数），写入 crawl_runs.note 与出勤简报 `coverage` 节——「0 新增」从此可自证（有水位、有页数）。
- 上限 8000/站，滚动丢最旧；`SPIDER_WATERMARK_DIR` 可重定向（测试）。

### 2. ccgp 深扫 + 已见边界早停（crawl/sources/ccgp.py）

- 页数上限 `SPIDER_CCGP_MAX_PAGES`（未设 = max(6, max_pages)），**整页原始已见即停**（时间倒序下更深页更旧，安全）。
- `fetch(keywords, max_pages, start_time, end_time)`：支持 timeType=5 指定时间段（YYYY:MM:DD），供回溯作业用。
- 列表块新增解析**代理机构**（此前只取采购人）——字段完整度白捡。
- runner 在过滤前合并水位（原始口径），note 增加 wm/pages 字段。

### 3. ccgp 回溯作业（scripts/jobs/backfill_ccgp_window.py）

- 按日切片扫 2026-07-01~08-31（62 天逐日请求），每片翻页到空/水位边界，同口径过滤后入库。
- **断点续扫**：状态存 `data/watermark/ccgp_backfill_state.json`；频控/网络失败如实停、状态不推进，下次续跑。
- ⚠️ 实跑状态：ccgp 当前对本机 IP 持续频控（多次探针+作业首日即拦，冷却阶梯不轰炸），**作业已交付未跑通**，待解封（建议 WebBridge 双IP 预热后或次日执行）。

### 4. 公司视角线索口径（可投标线索）

- `/api/notices?actionable=1`：notice_stage ∈ {intent, bidding, change}（意向/招标/更正）。
- 台账列表新增「仅可投标线索」复选框**默认勾选**；CSV 导出同步。
- 实测：60 条总量 → 23 条可投标线索；结果/终止等 37 条归入背景（详情抽屉时间线里仍可见，供做标书参考）。

### 5. 关键决策字段自动回填常态化（出勤内建）

- `crawl/backfill.py auto_backfill_pass`：每轮出勤后自动执行——对**可投标阶段（意向/招标/更正）且缺金额**的 ccgp/ggzy/jsggzy 新条目按条回填（金额/项目编号/截止时间/摘要，ggzy b 页结构化字段实测可得），每站每轮 ≤5、失败如实记 detail_status、单条异常不炸出勤；`SPIDER_NO_AUTO_BACKFILL=1` 可关。
- 报告/简报新增 `autoBackfill` 节；契约 output 不含 notice_stage，自动回填用后即删临时字段（契约测试守住 9 字段）。
- ccgp 列表自带采购人/代理（本轮起入库）；江苏/采招附件按需（P5/P6 已接）。
