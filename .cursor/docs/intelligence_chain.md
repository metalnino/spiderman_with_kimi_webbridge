# 全数据链情报体系 · 第一性原理分析与落地（entity_intel）

> 背景：把「采集员收集公告」升维到「经营客户 + 预测机会 + 闭环成交」。
> 本文回答三个问题：这件事的本质是什么、可不可行合不合理、对企业有没有意义，然后给出现已落地的方案与后续路线。
> 配套交付：`.cursor/docs/entity_intel_delivery.md`（代码/测试/契约清单）。

## 一、结论先行

1. **本质**：用户描述的不是「采集员扩边界」，而是把「事件流」升维成「实体图」。公告是一条条流；真正值钱的是**实体 + 关系 + 时间规律**的图。
2. **可行性**：分两期。**一期（本次已落地）确定性可行**：实体聚合、中标企业抽取、历史周期粗估、原发渠道。**二期（需时间累积 + LLM + 人在环）**：精确预测、资质要求语义、投标/分包闭环。
3. **合理性**：方向正确，但有两处必须纠正——「推算将来招标日期」是**窗口提示不是日期事实**；「中标企业→分包商」是**商务关系不是数据可推导**。这两处若当成自动结论，是危险的过度承诺。
4. **企业意义**：把生意从「被动刷公告、赶 deadline」变成「主动经营每个复购客户、提前备标」。数据资产随时间**复利**——这是它和「抓一批公告」的本质区别。

## 二、第一性原理拆解

把用户的原话拆到最基本事实：

| 用户描述 | 最基本事实 | 数据类型 |
|---|---|---|
| 会存在业务的实体 | 采购人/招标人（谁在买） | 需求侧节点 buyer |
| 官网招标网址 / 官方渠道 | 每个实体的信源（原发寻址） | 实体的属性 |
| 历史招标信息 / 周期 | 同一实体历次公告的时间序列 | 实体的时间规律 |
| 历史招标要求 | tenderFile 里的资质/评分语义 | 事件的内容（语义） |
| 中标企业 / 分包商 | 谁中标了（谁在做） | 供给侧节点 winner |
| 推算将来招标日期 | 周期中位间隔的外推 | 预测（启发式） |
| 闭环（投标/直营/分包） | 商务决策 | 人在环，不自动 |

**关键判断：一个图，两类节点。** 采购人（buyer，你的客户）和中标企业（winner，你的对手同时也是潜在分包商）是**两类不同节点**，中间以「某项目被谁中标」的关系边连接。之前的系统只有 buyer 这一类，缺 winner——这正是闭环里「拿本地分包商去做」那一半缺失的根因。

**再一个关键判断：实体图要吃「累积库」，不是单轮 handoff。** 采集员产出单轮事件流；实体层要的是跨轮、多年的累积历史。所以实体情报员的输入是 `notices` 累积库（DB），不是某一次采集的交接物。这是它与解析员（吃单轮 tenderFile）的架构区别。

## 三、现状对账（代码/表为证）

| 能力 | 现状 | 判定 |
|---|---|---|
| 采购人实体 | `Notice.buyer` 采集 + `notices.buyer` 落库 + `entities` 表 + `build_crm_db` 全国同名合并 | ✅ 已存在但散在平台层 |
| 阶段时间线 | `stage.py` 全阶段 + `project_key` 项目聚合 | ✅ P4 已存在 |
| 周期粗估 | `entities.next_bid_hint` 中位间隔 | ✅ 已有粗版 |
| 原发渠道 | `notices.original_url/origin_source` + `origin.py` | 🔶 半填 |
| 中标企业 winner | **无字段、无抽取** | ❌ 唯一真缺（本次补齐） |
| 闭环决策 | `lead_status` + CRM UI | 🔶 人在环（正确） |

所以「当下只做很小一部分」的精确表述是：**图纸画了 60%、管线只接了 10%、闭环缺最关键的中标企业节点**。本次把缺的那块补上，并把散的接成岗。

## 四、可不可行、合不合理（给方案前的判断）

**可行的部分（一期，确定性）：**
- 采购人实体聚合：纯规则（名称规范化 + 全国同名合并），可行。
- 中标企业抽取：结果公告的标题/摘要里写明了「中标/成交供应商：XX」，是**已采到但被丢弃**的数据；用确定性正则抽出来即可。前提是诚实——登录墙/无摘要时如实 null。
- 周期粗估：中位间隔外推，对「年度续签」类合同（绿植租摆正是年度制）足够有用。
- 原发渠道：`origin.py` 已具备，聚合到实体即可。

**现在不可行 / 只能给提示的部分（诚实划线）：**
- **精确预测日期**：周期是启发式，样本少时置信度低。必须输出 `confidence`，把它当「提醒窗口」不当「事实」。
- **历史招标要求语义**：需要 LLM 解析 tenderFile（解析员岗位，在兄弟工作区），且要多年历史才有价值。历史当前只有约 2 个月窗口。
- **中标企业 → 分包商**：数据只能告诉你「谁中标了」，不能告诉你「他愿不愿意分包给你」。这是销售关系，不是数据推导。
- **闭环成交**：投标/不投、直营/分包是业务决策，红线永远不自动。

**给方案后的验证结论（本次落地后）：**
- 28 个新增单测 + 243 项全量回归通过；中标企业抽取对真实句式（括号注释、金额噪声、多候选人、流标/废标、登录墙）逐条诚实处理。
- 一期方案**成立且合理**；二期必须等历史累积，且保留人在环，不做自动决策。

## 五、企业意义（为什么值得做）

1. **从被动到主动**：现在是「公告出来才看见、赶 deadline」；做完后是「知道每个复购客户大概几月招标，提前一个月备标」。
2. **数据复利**：公告是消耗品，实体图是资产。每多一轮采集，实体历史越厚，周期粗估越准——越用越值钱。
3. **打开供给侧**：winner 节点让「拿不下总包就找本地中标方分包/供花」从设想变成可查询的数据。
4. **决策前置**：备标（写方案、理解资质要求、维护关系）要几周，靠「提前知道窗口」抢出这段时间，是竞争胜负手。

## 六、岗位分层（边界收口）

全数据链是 4 层产品，不是 1 个采集员膨胀：

| 层 | 岗位 | 契约 | 状态 |
|---|---|---|---|
| L1 事件流 | 招标采集员 | collector/v1.2.0 | 已存在 |
| L2 实体图 | **实体情报员** | **entity_intel/v1.0.0** | **本次新增** |
| L3 语义 | 解析员 | parser/v1.1.0（兄弟工作区） | 已存在 |
| L4 决策 | 商务/CRM | 人在环，不自动 | 已存在（lead_status） |

规则：**每上一层都经过「抽取→落库→交接物」，绝不往下层员工身上堆功能。** 红线三条不变：不读语义（L2 只抽名字不判断）、不做业务决策（L4 人在环）、不造假（抽不到 null）。

## 七、一期落地方案（已实现）

新增「实体情报员」`crawl/intel_employee.py`（implements `entity_intel/v1.0.0`），确定性四层：

- **契约 input**：`dateRange / regionFilter / platforms / extractWinners`。
- **契约 output**：`{entities, winners, relations}`。
  - `entities`：采购人实体（名称/城市/公告数/最近公告/下次粗估/置信度/原发渠道/业务标签）。
  - `winners`：中标企业（名称/采购人/项目/中标时间/抽取来源）。
  - `relations`：供需关系边（buyer → winner）。
- **观测**：`reports/intel-report.json` 7 项指标（含 `winner_extract_rate`，无结果公告时 null）。
- **交接物**：`handoffs/intel/latest.json` + 归档。
- **抽取**：`crawl/winner_extract.py`（中标企业）、`crawl/entity_aggregate.py`（实体聚合+周期粗估，CRM 同源复用）。
- **入口**：`scripts/intel_run.py`。
- **schema**：`notices.winner`（schema.sql + migrate_ops.py）。

## 八、后续路线（二期，需历史累积）

1. **历史深度**：对 top 实体回溯 1-3 年（采集窗现在只有 2 个月），周期粗估才有置信度。
2. **要求语义**：解析员把 tenderFile 抽成结构化「资质/评分/服务要求」，接进实体。
3. **原发渠道回填**：把 `origin.py` 的原发寻址纳入实体聚合，做到「每个实体→官方招标网址」。
4. **闭环（人在环）**：把 winner 关系喂给 CRM，人工判断「直营 or 找分包」，系统只提供名单与证据，永不自动决策。

## 九、诚实限制（不可抗力与边界，记录在案）

- 中标企业抽取依赖 `summary` 已回填；chinabidding/cebpub 登录墙、vaptcha 未过时如实 null，绝不用摘要冒充中标方。
- 真机冒烟（2026-08-26）：result 公告 191 条里 188 条 summary 为空（采集员只对可投标阶段回填详情，结果公告未回填）→ 本轮 winner=0。这是数据未回填、非代码缺陷；二期对 result 公告做详情回填后即可产出中标企业。
- 周期粗估是启发式，样本 < 2 时为空；`confidence` 只分 low/medium/high，不承诺精确日期。
- 历史窗口当前仅 2026-07~08，多数实体样本不足，粗估多为空——这是数据事实，不是缺陷，随时间自愈。
